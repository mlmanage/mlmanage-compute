# Controllers and webhooks

## Kopf task controller

Source: `devops-backend/controllers/task_controller.py`

Deployment: `devops-backend/controllers/controller-deployment.yaml`

### Behavior

- `@kopf.on.create('devops.local', 'v1', 'tasks')`
  - Creates a Pod named `task-<task-name>` in the Task namespace.
  - Labels Pod with `app=task`, `task-name=<task-name>`, `user=<spec.user>`.
  - Container name: `main`.
  - Container image: `spec.image`.
  - Container command: `spec.command` or `['sleep', 'infinity']`.
  - Container resources: `spec.resources`.
  - Env vars: `USER_NAME`, `PROJECT_NAME`, and (when `spec.vramLimitGB` is set) `VRAM_LIMIT_MB` = `vramLimitGB × 1024`.

- `@kopf.on.timer(..., interval=30)`
  - If status phase is `Running` and `timeLimitSeconds` is exceeded, deletes the Pod and sets Task status to timeout.

- `@kopf.on.delete(...)`
  - Deletes associated Pod from Task status.

### GPU selection behavior

If `resources.limits.nvidia.com/gpu > 0` and `spec.gpuUUID` exists, the controller adds a node selector:

```yaml
nodeSelector:
  nvidia.com/gpu.uuid.<gpuUUID>: "true"
```

Verify actual node labels before relying on this format.

## VRAM mutating webhook

Source: `devops-backend/gpu-operator/webhook.py`

Deployment: `devops-backend/gpu-operator/vram-webhook.yaml`

Certificate/config script: `devops-backend/scripts/generate-webhook-certs.sh`

### Behavior

- HTTPS server listens on port `8443`.
- Handles only `POST /mutate`.
- Skips Pods in `devops-system` and Pods labeled `app=vram-webhook`.
- If the first container already has `VRAM_LIMIT_MB` (set by the controller from the Task's `vramLimitGB`), the webhook leaves it unchanged.
- Otherwise it injects a default into the first container:

```yaml
- name: VRAM_LIMIT_MB
  value: "4096"   # configurable via DEFAULT_VRAM_LIMIT_MB on the webhook Deployment
```

This makes the effective VRAM limit per-task: tasks submitted with `vram_limit_gb` get that value; others fall back to the webhook default.

### MutatingWebhookConfiguration

Generated by script as `vram-limit-webhook`.

It intercepts Pod `CREATE` operations for core/v1 Pods except excluded namespaces/objects.

## Disk quota controller

Source: `devops-backend/quotas/disk-quota-controller.py`

Deployment: `devops-backend/quotas/disk-quota-controller.yaml`

### Behavior

- Loads in-cluster Kubernetes config.
- Starts Prometheus HTTP server on port `9090`.
- Every 300 seconds:
  - Lists namespaces with `devops.dev/user-namespace=true`.
  - Lists PVCs in each namespace.
  - Classifies volume type by PVC name containing `home`, `scratch`, or `project`.
  - Attempts to run a BusyBox Pod and execute `df -k /mnt`.
  - Emits gauge `user_disk_usage_percent{user,volume_type}`.
  - Posts alert JSON to `http://devops-api.devops-system.svc:8000/internal/alerts` if usage > 80%.

### Known issues

- The temporary BusyBox Pod does not mount the PVC being checked.
- The API does not implement `/internal/alerts`.

## Reservation reminder CronJob

Manifest: `devops-backend/reservations/reminder-cronjob.yaml`

- Schedule: `0 8 * * *`.
- Container: `curlimages/curl:latest`.
- Calls `/reservations/calendar` and echoes reminder lines.

Caveat: the script uses `jq`, but the `curlimages/curl` image may not include `jq`; verify before relying on it.
